# 故事生成与分享试用评估

评估日期：2026-09-30。范围：匿名用户上传画作、生成四页故事、阅读、分享图片。不要求登录注册、支付或跨设备同步。

## 结论

当前不建议直接开放给用户独立测试。可继续受控联调；完成线上首次访问可靠性、真实生成与手机分享验收后，可小范围邀请测试。无登录注册不是阻塞项，现有随机浏览器凭据可以承担匿名任务归属，但不能承担防刷或跨设备恢复。

## 阻塞与证据

| 优先级 | 发现 | 判断与下一步 |
| --- | --- | --- |
| P0 | 用户报告手机需多次刷新才能打开；对仓库配置域名 huahuole.sidecraftlab.com 的 HTTP 检查返回 301，但本环境多次 IPv4 HTTPS 请求均报 SSL_ERROR_SYSCALL，对照 example.com HTTPS 成功 | 线上访问未通过。只能确认本环境到该域名的 TLS 链路异常，不能据此认定服务器证书错误或手机白屏根因；需确认实际 URL、设备、浏览器、网络，结合部署端 TLS/代理日志定位 |
| P0（公开试用） | backend/jobs.mjs 的 create() 对合法随机凭据即可接收任务；仅限制执行并发，没有每日总量、队列容量或费用熔断 | 匿名凭据可自行创建，并发上限不限制总账单。公开发链接前需全局配额/队列上限，并配合入口限流；少量邀请测试也应有明确预算停止机制 |
| P1 | 本次生成链路验证使用模拟模型 | 真实服务在当前部署上至少需完成一次上传→三页续画→刷新找回→分享，记录耗时、失败情况和实际费用；已有历史单图成功不替代当前全链路验收 |
| P1 | 分享是 canvas PNG 预览与 a[download] 保存，没有公开阅读链接；使用 roundRect、structuredClone 等较新接口 | Chrome 手机尺寸下载已通过，不代表 iOS/安卓/微信保存相册可用；需真机验证。若要求链接分享，则当前未实现 |
| P1 | 原图和故事以 Data URL 整册存入 IndexedDB，每次启动读入整册，每次保存写回整册 | 多作品、低内存手机的启动和保存风险尚未验证；应进行代表性容量测试，后续改为逐作品/Blob 存储 |

## 本次本地修复

- index.html：样式不再阻塞启动提示的绘制；应用等待样式就绪再展示。样式超时/失败有错误反馈，脚本加载失败明确提示，等待过长提供刷新入口，不清除用户数据。
- app.js：接口超时改用 AbortController 与定时器，覆盖读取响应体阶段，避免依赖旧手机浏览器缺少的 AbortSignal.timeout。
- app.js：匿名凭据的读取和首次创建放在一个 readwrite 事务中，避免同时打开两个新标签页产生不同凭据；保留现有凭据，并在画册交互前完成初始化。

这些修复不涵盖 HTML 到达浏览器之前的 DNS/TLS/代理故障，尚未部署，不能宣称用户手机白屏已经解决。

## 最小放行条件

1. 确认实际部署地址，修复首次访问问题；在目标手机/浏览器与 Wi-Fi、移动网络下各连续冷启动验证，无需靠刷新进入。
2. 部署本地修复，并完成真实生成、关闭页面后找回、PNG 分享保存的完整流程。
3. 对匿名调用设置可执行的总量/预算上限，达到上限时给出明确提示；保留任务归属检查。
4. 邀请测试时明确当前分享为图片、记录绑定当前浏览器、AI 结果需先预览；数据说明需与实际服务器保存行为一致。首页“仅在这台设备”等表述需避免让用户误以为生成数据不在服务器保留。
